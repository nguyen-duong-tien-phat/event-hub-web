# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with this repository.

## What this is

`event-hub-web` is the Admin and Organizer dashboard for EventHub. The API lives in a separate repo, `event-hub-dotnet` (`~/Documents/event-hub-dotnet`, .NET 10), and the mobile app in `event-hub-flutter`. This repo talks to the API over HTTP only: it shares no code with either. When the API and this repo disagree, the API's controllers and its `CLAUDE.md` are the truth.

Stack: React + Vite + TypeScript, Tailwind + shadcn/ui, React Router, TanStack Query and Table, React Hook Form + Zod, Sonner (toasts). Tests: Vitest + Testing Library + MSW. The UI is in English (the API's messages are English). Not in the MVP: check-in page, charts over time, i18n, dark mode, deploy.

## Commands

```bash
npm install
npm run dev        # Vite on http://localhost:5173
npm run build
npm run lint
npm test
```

- The API must be running for anything beyond the login screen: from `event-hub-dotnet`, `docker compose up -d postgres redis mailpit floci`, then run the API from `EventHub.API/` (port 8080). Its default `Cors__AllowedOrigins` is already `http://localhost:5173`.
- `VITE_API_URL` is the API base URL (default `http://localhost:8080`). Copy `.env.example` to `.env.local` to change it.
- Pushing an image to storage needs the bucket's CORS rule for `http://localhost:5173` (see the API README, "Event images and CORS").

## Rules that come from the API (do not work around them)

- **Tokens.** `POST /auth/login` returns `token` (access, 15 min) and `refreshToken` in the body; there are no cookies. Keep the access token in memory and the refresh token in `localStorage`, so a new tab or a restart stays signed in. Each refresh token works once: using it twice is treated as theft and ends every session of that user. So refresh through **one shared promise** per tab (concurrent 401s wait for the same `POST /auth/refresh`, then retry) and, across tabs, inside a **Web Lock** that reads the stored token only after the lock is held, so a tab never sends a token another tab already spent. A failed refresh logs the user out, and signing out in one tab (the `storage` event) signs out the others.
- **Role** comes from the login and `GET /auth/me` bodies, never from decoding the JWT (its role claim has a long Microsoft URI as its name). A role change or a blocked account reaches the user only when the access token is next refreshed (up to 15 minutes): say so in the Users page.
- **`Authorization` goes to the API only.** The poster upload is `POST /events/image-upload` (`{contentType}` → `{uploadUrl, fileUrl}`), then a plain `fetch` PUT of the bytes to `uploadUrl` with exactly that `Content-Type` and no `Authorization` header (the signature is in the URL, and the URL lives 5 minutes). Then send `fileUrl` as `imageUrl`; the API rejects any other URL. jpeg, png and webp only. The API has no size limit, so the form limits files to 5 MB itself.
- **Errors come in three shapes**, and `api/client.ts` turns them into one: `{message}` (400/403/404/409/429), `{message, traceId}` (500; show the `traceId` so it can be found in the API log), and ASP.NET validation `{title, errors: {Field: [...]}}` (400). 409 carries a message worth showing as is (deleting an event with bookings, a ticket that has sold). A blocked account's login answers 403 "This account has been blocked."
- **PATCH sends only what changed.** `startsAt` must be at least a day ahead, so re-sending an unchanged `startsAt` of an event that starts soon is a 400 even when only the title changed. `highlights` replaces the whole list (`[]` clears it).
- **Dates are UTC** in the API. Show them in the browser's time zone and convert for `<input type="datetime-local">`.
- **Lists** return `{items, page, pageSize, totalCount, totalPages}`; `pageSize` is 1 to 100. They are paged with OFFSET, so very deep pages are slow.
- **Permissions in the UI are a convenience.** The API decides: an Organizer sees and changes their own events (`GET /events?organizerId=<own id>`), an Admin everything and the Users page. Always handle a 403 even when the UI hid the button.

## Layout

```
src/
  api/        client.ts (fetch, refresh, error normalising), types.ts, one file per resource
  auth/       AuthProvider, useAuth, RequireAuth, RequireRole
  components/ ui/ (shadcn), shared pieces: DataTable, Pagination, ConfirmDialog, ...
  features/   login, events, stats, tickets, bookings, users (one folder each)
  lib/        formatting (money, dates), error helpers
```

Name files `<Thing>.tsx` for components and `<thing>.ts` for the rest. Components in `components/ui` are generated by the shadcn CLI: change them only when there is a reason.

## Working rules

- Do the work one step at a time. Show the diff and wait for the user to say "commit" before committing; push only when told.
- Do not add attribution lines to commit messages or pull request descriptions: no `Co-Authored-By: Claude ...`, no "Generated with Claude Code" or similar. Write them as plain text.
- Do not commit `.env*` files other than `.env.example`.
